# Native apps: the design system in Swift

Read this before you change Back Pocket, Field Guide or Workshopr Planner for Mac. The rules in `/DESIGN.md` hold for all three; this file says how they reach Swift, which tools find the right value, and which check holds an app to it. DESIGN.md §12.11 carries the rules a check enforces; everything else is here.

The binding for each app (paths, project, scheme, theme files, sanctioned scopes, hazards) is the `native` block of `workshopr-design-system.json`, and the enforcer MCP's `native_apps` tool prints it. Counts are never written here: `npm run lint:ds:native -- --all` prints the current state.

---

## Before you write Swift

1. **Get the binding.** Call the enforcer's `native_apps` with the app's key (`back-pocket`, `field-guide` or `planner-mac`). It returns the app's paths, its build, run and screenshot commands, its hazards and sanctioned scopes, and a live count of the native check's findings by rule.
2. **Find the value.** Call `list_tokens` with `platform: "swift"` and the same `app`. Each web token comes back as `Color(hex: 0xRRGGBB)` beside the app constants that mirror it, with any that drifted marked. With no filter it also lists the app's off-system constants.
3. **Use the theme file.** Take every colour, font, radius, space and duration from the app's theme files. If the value you need is not there, add a named constant to the theme file that mirrors a web token, then use the constant. A view never holds a value of its own.
4. **Check it.** Run the enforcer's `validate_file` on every Swift file you changed, then `npm run lint:ds:native`, and resolve anything new. For code you have not written to a file yet, `check_snippet` takes `language: "swift"` and an optional `file_path` that tells it which app, theme file or view the snippet belongs to.
5. **Look at it.** Build, run and screenshot it in the simulator in light and dark appearance and at the largest accessibility text size, and read its VoiceOver labels. No automated check here sees any of that.

## The token contract

- **`platform-tokens.css` is the source.** A native constant mirrors a web token's resolved value: the catalog's `tokens[name].resolved`, or its `value` when there is no `resolved`, in `components.generated.json`. When a web token moves, the constant should move with it.
- **Values live only in the theme files.** A view uses the constant (`WS.C.ink`, `Palette.border`, `Theme.brand`), never `Color(hex:)`, `Color(red:)` or a colour literal.
- **Back Pocket annotates.** Each colour constant ends with a `// --token-name` comment naming the web token it mirrors, and the check compares the constant with that token. Keep the annotation when you add a constant, and name the brand token (`--brand`, `--brand-ink`, `--brand-soft`, `--brand-tint`, `--brand-line`) rather than a legacy alias where one fits.
- **Field Guide and the Mac app match by value.** The check matches each constant to the web tokens with the same value. The Mac app carries no annotations; the Field Guide's `Tone` exercise and icebreaker `tint` and `pale` end with a `// --token-name` comment for people, which the check does not read. A constant whose value equals no web token is off-system.
- **Sanctioned scopes are the exception.** Field Guide's `Tone` (content-type hues per section) and the Mac app's `ActivityKind` (activity-type hues, the Planner exception in CLAUDE.md §11) are sanctioned in the manifest, so their values are not reported off-system. A new scope is sanctioned only with Bill's approval, in the manifest.
- **Names do not travel.** Map by value, never by name: the Mac app's `Theme.brandSoft` holds the web `--brand-tint`.
- **`Color(hexString:)` is for API data.** It parses colours that arrive from the server, such as category colours, and the check never flags it. It is not a way to write a design value.

## Finding a value

- `list_tokens` with `platform: "swift"` and `app`, as above. Add a filter to narrow it the way you would on the web.
- `native_apps` for an app's binding and its live findings.
- From the shell, `npm run lint:ds:native -- --app field-guide --all` lists every finding in one app, baselined ones included.
- When no web token fits, the value is a design decision, not a constant to invent. Ask Bill.

## Platform rules

- **Brand fonts.** Fraunces for headlines and display, Inter for everything read in volume, Material Symbols Outlined for icons. Each app bundles its own copies. Back Pocket (`FontRegistrar`, over `Resources/Fonts`) and the Mac app (`FontRegistry`) register them at launch with `CTFontManagerRegisterFontsForURL`; Field Guide lists them under `UIAppFonts` in `library-app/project.yml`. A font family that does not start with one of those names is off-brand.
- **Icons are a font.** A Material Symbols glyph is set as `Text` and hidden from VoiceOver. Back Pocket ships two subsets, outlined and filled, holding only the icons it uses and addressed by codepoint through its `MSIcon` enum. To add an icon there, look up its codepoint in Google's `MaterialSymbolsOutlined[FILL,GRAD,opsz,wght].codepoints`, add a case to `MSIcon`, and re-subset both fonts with that codepoint included (`workshopr-app/README.md`). Field Guide and the Mac app bundle the full variable font and address glyphs by ligature name through their own `MSIcon` views; the filled style sets the FILL axis.
- **Dynamic Type on iOS.** Text scales with the reader's setting: use `.custom(name, size: size, relativeTo: .body)`, with the text style that matches the role. `fixedSize:` ignores Dynamic Type, and `.system(size:)` on text is both off-brand and fixed. Field Guide's `Typo` uses `.custom(_:size:)`, which scales relative to body; Back Pocket's `WSFont` does not scale today (see Known drift).
- **44pt targets.** Anything tappable is at least 44 by 44 points, using a larger frame or `contentShape` when the glyph is smaller.
- **Labels.** Every icon-only control has an `accessibilityLabel`. Decorative glyphs and illustrations take `accessibilityHidden(true)`, as the icon views in all three apps already do. State is never carried by colour alone.
- **Reduced motion.** Read `accessibilityReduceMotion` from the environment (or `UIAccessibility.isReduceMotionEnabled`) and replace movement and scaling with a short fade. Back Pocket's `WS.Motion.animate` skips the animation when it is on, and Field Guide's `Motion.enter(_:)` falls back to opacity.
- **Light first.** Both iOS apps pin `.preferredColorScheme(.light)` at the root. Dark mode is a design decision, not a default.
- **No pure black.** Ink is `#2C2416`. `.foregroundStyle(.black)` is a violation; a black shadow such as `.shadow(color: .black.opacity(0.1), ...)` is fine.
- **Warm stone greys.** Greys come from the stone ramp (`--gray-*`), never cool greys.

## Motion

Durations and curves belong in the app's motion file and mirror `/motion.md` and the `--duration-*` and `--ease-*` tokens: UI motion runs 150 to 300ms, entrances decelerate, exits accelerate, nothing overshoots, `--ease-spring` (0.16, 1, 0.3, 1) settles things into place, and `--ease-reveal` (0.22, 1, 0.36, 1) is the entrance curve.

- **Back Pocket:** `WS.Motion` in `Theme/Motion.swift`, with the press styles `WSPressStyle` and `WSLiftStyle`.
- **Field Guide:** `Motion` in `Theme/Motion.swift`, with `PressableStyle`, the `reveal(_:)` entrance and the `Haptic` vocabulary.
- **Workshopr Planner:** no motion file yet. Its few animations are inline in the views, mostly 0.15s and 0.3s ease-out.

Add a duration or curve to the motion file, never inline in a view. Where each app departs from the web values today is listed under Known drift.

## Build, run and screenshot

Run everything from the repo root. Never open a shell inside `workshopr-app/WorkshoprApp/` (see Hazards).

**Back Pocket**

```bash
xcodebuild -project workshopr-app/WorkshoprApp.xcodeproj -scheme WorkshoprApp \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
xcrun simctl launch booted io.workshopr.pocket -screen tips   # Debug builds: home, interventions, card, tips, tip, saved
```

**Field Guide**

```bash
xcodegen generate --spec library-app/project.yml   # after adding or removing a file
xcodebuild -project library-app/WorkshoprLibrary.xcodeproj -scheme WorkshoprLibrary \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
SIMCTL_CHILD_WORKSHOPR_ROUTE=exercise:12 xcrun simctl launch booted io.workshopr.library   # Debug builds read WORKSHOPR_TAB and WORKSHOPR_ROUTE
```

**Workshopr Planner (Mac)**

```bash
swift build --package-path mac-app
swift run --package-path mac-app
mac-app/scripts/make-app.sh   # writes "Workshopr Planner.app" to mac-app/dist
```

## The checks

The enforcer's `validate_file` and `check_snippet` and `npm run lint:ds:native` run the same Swift rules. Comments are ignored except for Back Pocket's annotations, and `ds-lint-disable-line` or `ds-lint-disable-next-line` in a comment suppresses one line, as on the web. A Swift file outside every app still gets the generic rules, with web tokens as suggestions. `fix_file` never rewrites Swift: it returns the violations and says there are no safe automatic fixes.

| Rule | Severity | Where | Fires on |
|---|---|---|---|
| `native-token-drift` | high | theme files | A constant annotated with a token whose value differs from the token's resolved value. The message names both, for example "WS.C.inkMuted is #78716C but --text-muted is #706965". |
| `native-unknown-token` | medium | theme files | An annotation naming a token the catalog does not have. |
| `native-off-system` | medium | theme files | A constant whose value equals no web token, in a scope the app's `sanctionedScopes` does not list. It suggests the nearest token. |
| `native-hex-in-view` | high | other Swift files | A numeric colour literal in `Color(hex:`, `Color.init(hex:`, `.init(hex:`, `Color(red:`, `Color(.sRGB, red:`, `UIColor(red:`, `NSColor(red:` or `#colorLiteral`, across line breaks and with any opacity, but not `Color(hexString:` and not a colour computed from variables. It suggests the theme constant with the same value when one exists, else a new named constant in the theme file and the nearest web token. |
| `native-pure-black` | high | any Swift file | `.foregroundStyle(.black)`, `.foregroundStyle(Color.black)`, `.foregroundColor(.black)` or `.foregroundColor(Color.black)`. A black shadow is fine. |
| `native-off-brand-font` | high | any Swift file | A family in `.custom("`, `Font.custom("`, `UIFont(name: "`, `NSFont(name: "`, `UIFontDescriptor(name: "` or `NSFontDescriptor(name: "` that does not start with a brand or icon font name. `Fraunces72pt-Bold` and `Inter-Regular` pass. |
| `native-system-font` | medium | any Swift file | `.system(size:` on a line that also has `Text(`. Sizing an SF Symbol image with `.system` is fine. |
| `native-fixed-font` | medium | iOS apps only | `fixedSize:` inside a `.custom(` text font, which ignores Dynamic Type. It suggests `.custom(name, size:, relativeTo:)`. An icon font is exempt: a glyph is sized to its frame, and scaling it would clip it. |

**`npm run lint:ds:native`** checks every app in the manifest (its theme files and every Swift file under its source), or only the files you pass. `--app <key>` limits it to one app and `--json` prints machine output. It compares the findings with `native-baseline.json`, keyed by app, rule, file and match with a count and no line numbers, so an unrelated edit does not churn it. It prints new findings and exits 1 when there are any, then says how many baselined findings remain and how many were fixed since. `--all` prints the baselined findings too. A drift key carries the constant's value, so a drifted constant that moves to another wrong value is a new finding; renaming a file makes all of its findings new. `--baseline` rewrites the file, and only Bill approves a rebaseline, the same policy as `check-page.php --baseline`. `npm run check:ds` runs it over the Swift files you pass, or over every app when you pass none.

## Hazards

- **Never run a shell from inside `workshopr-app/WorkshoprApp/`** or any folder under it. The oh-my-claudecode hooks write `.omc/` state into the shell's working directory; Back Pocket's synchronized root group bundles every file there, hidden folders included, and the build fails with "Multiple commands produce". Use paths from the repo root.
- **Field Guide's project is generated.** A file you add is not in the build until `xcodegen generate` runs, and a hand edit to `WorkshoprLibrary.xcodeproj` is lost the next time it does.
- **The Mac app is signed for this Mac only.** `make-app.sh` assembles and signs the bundle in a temporary folder, because iCloud Desktop sync stamps Finder metadata that `codesign` refuses, and the signature is ad hoc. Sharing it needs a Developer ID signature and notarization.

## Known drift, decisions for Bill

These are the open questions from the survey of 19 October 2026. None is fixed here, because the apps change only when Bill decides; `npm run lint:ds:native -- --all` prints where each stands now.

**Back Pocket**

- `WS.C.bgPage` is `#FEF7F1`, annotated `--bg-page`, but `--bg-page` is `#FAFAF9` and the catalog records the cream as legacy, not to be restored. Move the app to the web ground, or keep the cream as a deliberate app ground under a different annotation?
- `WS.C.inkMuted` is `#78716C`, annotated `--text-muted`, which moved to `#706965` on 6 October 2026 for AA contrast. Follow it?
- `WS.C.gray300` is `#D6D3D1`, annotated `--input-border`, which is now `--gray-200` (`#E7E5E4`). Follow the token, or re-annotate the constant as `--gray-300`?
- `WS.C.surface` is white, annotated `--bg-surface / --card-bg`, but `--card-bg` is now the warm paper `#F7F1EA`, so the app's cards are white where the web's are paper. Which should the app's cards be?
- `WS.C.brandGradient` runs `#E54D4D` to `#C73E3E`; `--mainsite-gradient` runs `#D13A3A` to `#C73E3E`. Match it?
- The annotations name legacy aliases such as `--mainsite-primary` and `--phase-learn-dark`, which CLAUDE.md §11 rule 4 asks code to move off. Re-annotate them to the brand tokens?
- Every `WSFont` helper builds a fixed-size font (`heading` and `body` pass `fixedSize:`, and `headingBlackItalic` builds a `UIFont` at a fixed size), so no text in the app follows Dynamic Type. Moving to `relativeTo:` changes every screen at large sizes, so it needs a design pass. When?
- `WS.Motion.fast` is 0.1s and `WS.Motion.slow` 0.35s, against 150ms and 300ms on the web, and `WS.Motion.pop` is a spring that overshoots (damping 0.5), which motion.md rules out. Align them?

**Both iOS apps**

- The legacy cream also lives where no rule reads it: the launch screen colour (`workshopr-app/WorkshoprApp/Assets.xcassets/LaunchBackground.colorset` and `library-app/WorkshoprLibrary/Assets.xcassets/Paper.colorset`) and the section fade in `library-app/WorkshoprLibrary/Components/Backgrounds.swift`, which spells the paper as a byte triple. Moving `WS.C.bgPage` or `Palette.paper` alone would leave the cream on the launch screen and in the fade.

**Field Guide**

- `Palette.paper` is the same legacy `#FEF7F1`.
- `Palette.brandInk` (`#9F2F2F`) and `Palette.brandTint` (`#FDECEC`) are not web tokens: `--brand-ink` is `#C73E3E` and `--brand-tint` is `#FEF2F2`. Adopt the web reds, or add tokens for these?

- `Palette.muted` (`#57534E`) and `Palette.faint` (`#78716C`) match `--gray-600` and `--gray-500`, so the check passes them, but the web's muted and faint text are `#706965` and `#A8A29E`. The names promise one ladder and the values give another.
- Views hold colour literals, for example `0xFBD5D5`, the underline band in `App/IntroView.swift` and `Screens/Home/HomeView.swift`.
- `Tone` applies the content-type hues to whole sections (the tab tint and the screen gradient), wider than the Planner canvas exception CLAUDE.md sanctions. The manifest sanctions the scope pending Bill's confirmation. Confirm it, or narrow it?
- `Motion.standard` (0.2, 0, 0, 1) and `Motion.accelerate` (0.3, 0, 1, 0.3) are not the web curves, `--ease-in-out` (0.4, 0, 0.2, 1) and `--ease-in` (0.4, 0, 1, 0.2). Align them, or record them as the native curves?

- `Theme.brandSoft` is `#FEF2F2` and `Theme.brandTint` is `#FEE2E2`, the reverse of the web names (`--brand-soft` is `#FEE2E2`, `--brand-tint` is `#FEF2F2`), so an agent mapping by name gets the wrong red. `Theme.page` carries the comment `--brand-soft` but holds `#FEF2F2` too.
